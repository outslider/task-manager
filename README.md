# タスク管理システム

社内向けのプロジェクト／タスク管理 Web アプリです。
バックエンドは Python 標準ライブラリ + PyMySQL、データベースは **MariaDB / MySQL**、
フロントエンドはビルド不要の素の JavaScript（ES Modules）で構成しています。

- 依存パッケージは **PyMySQL 1 つだけ**。Node.js もビルドツールも不要です。
- 画面は PC・タブレット・スマートフォンに対応（レスポンシブ、ダークモード対応）。
- ガントチャートは **PowerPoint のスライドサイズで PNG / SVG 書き出し**ができます。

## 機能一覧

| 要件 | 実装 |
|---|---|
| タスクリスト（新規・編集・削除） | プロジェクトごとのツリー表示。行のドラッグで並べ替え・階層移動、`⋯` メニューから複製操作 |
| 階層化（子・孫…） | 親子関係を最大 8 階層まで。子の進捗は親に自動集計（加重平均）、期間も自動で親に反映。**親の付け替えはドラッグ・行メニュー・詳細画面のどこからでも**（子タスクごと移動） |
| ガントチャート | 日／週／月／四半期スケール、依存線、マイルストーン◆、本日ライン、タスク名列は横スクロールしても固定。一番下の行をドラッグしてその期間でタスクを追加。折りたたみ・区切り行・バー横の表示項目の切り替え。**全プロジェクトを 1 枚に並べる俯瞰表示** |

| ユーザー・グループ・権限管理 | 管理者／メンバーの全体ロール＋プロジェクト単位の 4 段階権限。グループ単位の権限付与も可能。**参加していないプロジェクトは一覧にも検索にも出ません** |
| スマホ対応 | 下部タブナビ、1 行 2 段のコンパクト表示、ドロワー全画面化 |
| プロジェクト管理 | プロジェクト単位のタスク・メンバー・色・アーカイブ。カードに参加メンバーの顔を表示 |

| 個人 ToDo | どのプロジェクトにも属さない、**自分だけに見える**覚え書き。1行入力で追加でき、育ったらタスクに引き上げられます。**毎月1日のことを3日前に出す**といった繰り返しも登録できます |
| Excel / CSV からの一括取り込み | Excel の範囲をそのまま貼り付けるか CSV を選ぶだけ。列の対応づけは自動で推測し、字下げはそのまま階層になります |
| まとめて編集 | 一覧でチェックして、担当者・状態・カテゴリ・期限の一括変更、日程の一括シフト、一括削除 |
| 祝日対応 | 日本の祝日を自動計算（春分・秋分・振替休日・国民の休日を含む）。ガントで網掛けし、負荷計算ではその週に使える時間を減らします。会社独自の休業日も登録できます |
| 横断検索 | タスク・課題・コメント・プロジェクト・自分の ToDo をまとめて検索（`/` キー）。参加していないプロジェクトのものは出ません |
| メモ・コメントで進捗共有 | タスクごとのコメント欄。状態／進捗／担当／期限の変更は自動で履歴として残ります。**`@` でメンバーを呼べ、URL はそのまま貼るとリンクになります** |
| リンク・ファイル添付 | ドラッグ＆ドロップのファイル添付（既定 25MB/件）と URL リンクの登録 |
| 期限アラーム・メール通知 | 期限超過／本日期限／期限間近をアプリ内通知＋メールで送信（重複送信なし）。**種類ごと・プロジェクトごとに送る／送らないを選べます** |
| 日次の進捗確認 | 「今日の確認」画面で担当タスクを一覧し、`0/25/50/75/100%` ボタンとメモでまとめて更新 |
| 先の見通し | マイタスクに**週ごとの山グラフ**。どの週に仕事が寄っているかが一目で分かり、棒をクリックするとその週だけ絞り込めます |
| 担当者設定 | タスクごとの担当者、担当者変更時の自動通知 |
| マイルストーン | マイルストーンフラグ。ガント上は◆で表示 |
| タスクのカテゴライズ | 既定で7分類（調査・リサーチ／設計・企画／実装・構築／ドキュメント作成／会議・打ち合わせ／事務・申請系／トラブル対応・障害対応）。**画面から追加・改名・並べ替え・削除ができ、記号は用意した中から選びます**。一覧の絞り込みとガントの色分けに対応 |
| 状態のカスタマイズ | 5つの状態（未着手／進行中／レビュー中／完了／ブロック中）の**名前・色・並び順**を変更可能。色は配色セットからまとめても選べます |

| 重要度 | 低／中／高／最重要の4段階。一覧では高以上に `!` `!!` を表示。ガントの色分けにも使用 |
| 依存関係とボトルネック | 先行タスクを設定すると依存グラフを解析し、**影響波及数・クリティカルパス・日程の矛盾**を自動抽出。専用の分析画面あり |
| チケット（受付窓口） | プロジェクトの外から飛んでくる**依頼・問い合わせ・障害報告**を受ける窓口。誰でも起票でき、受付待ち→対応中→完了で回します。作業が要るものは**タスクへ**、決めないと進まない論点は**課題へ**そのまま渡せます |
| チケットの集計 | 日次・週次で「受けた数」と「片付いた数」を並べ、溜まっているかどうかを見ます。担当者別・分類別・窓口別・種別別の内訳と平均対応日数つき。CSV に落とせます |
| 課題管理表 | タスクとは別建ての課題ログ。No.／区分／影響度／状態／対応者／発生日／期限／解決日／対応方針を管理し、**課題とタスクを相互に紐づけ**られます。CSV 出力対応 |
| 画面の色合い | アクセントカラーをプリセット8色＋任意の色から選択。ライト／ダーク／端末設定に追随。組織の既定色を管理者が設定し、各自が上書き可能。ロゴも選んだ色に追随します |

| 会議メモから一括起票 | 議事録を貼り付けると、やることだけを拾って一覧にします。担当者（「鈴木さん」のような書き方でも名寄せ）・期限・カテゴリ・重要度まで埋めた状態で、画面で直してから必要なぶんだけ登録できます |
| 進行レビュー | 期限超過・クリティカルパス・日程の矛盾・担当者ごとの負荷をまとめて渡し、「今週どこが危ないか」「先に何をすると効くか」を書いてもらいます。押したときだけ実行します |
| 工数と負荷の可視化 | 見積・実績工数（**すべて任意**）。担当者 × 週の負荷ヒートマップ、見積精度。工数が未入力でも件数ベースで機能します |
| 定例タスクの自動起票 | 毎週／毎月／毎日の規則で、期限の N 日前にタスクを自動作成。既存タスクから「定例にする」でも登録できます。**親タスクにまとめればガントでは1行**、「次回を飛ばす」で休みにも対応 |
| Slack 通知 | 期限超過・本日期限のまとめと、影響度の高い課題の起票を Slack へ。流す内容は全体／プロジェクトごとに選択可。インターネット公開は不要です |
| タスクの自動分解 | 「サーバ移行」のような大きなタスクを「事前バックアップ→検証→切替→疎通確認→旧環境停止」のような子タスクに分解して提案。期間があれば日程も按分します |

その他: 全文検索、担当者／状態／カテゴリ／プロジェクトでの絞り込み、
チェックイン連続日数、通知インボックス、ダークモード。

> 重要度と緊急度について: 緊急度は期限から自動的に決まるため、手で設定するのは**重要度**だけです。
> 「重要度 × 期限 × 依存関係」の3つから、日次画面とボトルネック画面が「いま何をやるべきか」を組み立てます。

## セットアップ

### 1. データベースを作る

```bash
sudo mysql -e "
CREATE DATABASE task_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tmapp'@'localhost' IDENTIFIED BY '安全なパスワード';
GRANT ALL PRIVILEGES ON task_manager.* TO 'tmapp'@'localhost';
FLUSH PRIVILEGES;"
```

文字コードは必ず `utf8mb4`（絵文字・機種依存文字対応）にしてください。

### 2. アプリを配置して依存パッケージを入れる

```bash
cd /opt/task_manager
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 3. 設定ファイルを用意する

```bash
cp config.ini.example config.ini
vi config.ini          # DB 接続情報とポートを記入
```

環境変数でも指定できます（環境変数が優先）。

| 環境変数 | 既定値 | 説明 |
|---|---|---|
| `TM_DB_HOST` / `TM_DB_PORT` | `127.0.0.1` / `3306` | DB 接続先 |
| `TM_DB_NAME` / `TM_DB_USER` / `TM_DB_PASSWORD` | `task_manager` / `tmapp` / — | DB 認証情報 |
| `TM_HOST` / `TM_PORT` | `0.0.0.0` / `8080` | 待ち受けアドレス |
| `TM_BASE_PATH` | （空） | サブディレクトリ公開時のパス（例 `/tasks`） |
| `TM_MAX_UPLOAD` | `26214400` | 添付ファイル上限（バイト） |
| `TM_SECURE_COOKIE` | `0` | HTTPS 公開時は `1` |
| `TM_ADMIN_EMAIL` / `TM_ADMIN_PASSWORD` | `admin@example.com` / 自動生成 | 初期管理者 |

### 4. スキーマを作成する

```bash
.venv/bin/python server.py --init-db
```

テーブルは起動時にも自動作成されるため、通常この手順は省略できます。
スキーマの内容は [`docs/schema.sql`](docs/schema.sql) を参照してください。

本番環境では実行しないでください。

## 使い方

### 今日の確認（日次アップデート）

ログイン直後の画面です。担当タスクが
**期限超過 / 本日期限 / まもなく期限 / 期限未設定 / 1週間動きのないタスク** に分類されます。

1. 各行の `0% 25% 50% 75% 100%` ボタンで進捗を指定（100% を押すと自動で「完了」になります）
2. 状態を変えたい場合はプルダウンから選択
3. `💬` ボタンでひとことメモと実績時間（メモはタスクのコメントとして記録されます）
4. 画面下部に出る **「まとめて更新」** で一括保存

保存すると変更内容が自動的にタスク履歴に残り、関係者に通知が飛びます。
チェックインした日は連続日数としてカウントされます。

画面は「今日どうするか」に絞って出します。

上の 6 つの数字（**期限超過 / 本日期限 / 担当の課題 / 担当のチケット / まもなく期限 /
直近7日の完了**）で、**スクロールしなくても全体の量が分かります**。
0 でないものを押すと、その欄まで飛びます。

並びは **いま見るもの**（期限超過 → 本日期限 → 自分が対応者の課題 → 自分が担当のチケット）
が先、区切りをはさんで **そのあとで見るもの**（まもなく期限 → マイ ToDo → 先の予定 →
期限未設定 → 動きのないタスク）が続きます。

- **期限超過 / 本日期限 / まもなく期限** は開いたまま、**先の予定 / 期限未設定 /
  1週間以上動きのないタスク / 直近7日で完了したタスク** はたたんで件数だけ見せます
  （見出しを押すと開き、その状態は次回も引き継がれます）
- 「1週間以上動きのないタスク」には、**開始日がまだ来ていないタスクは入りません**
  （始まっていないものが動かないのは当たり前なので）
- 上の集計カードは、**0 件のものは数字を薄く**して、目が要対応へ向くようにしています
- 状態のバッジは、**未着手だけ点線の枠で塗らない**ようにしています。
  淡い色どうしだと未着手と進行中が見分けづらいため、色ではなく形で分けています
- 各行にはカテゴリの記号が付きます
- メモと実績時間は `💬` を押したときだけ開きます（毎日入れるものではないため）

タスクのほかに、**自分が対応者の課題**、**自分が担当のチケット**、**マイ ToDo** も
続けて並びます。種類を取り違えないよう、**カードの左に色帯**（タスク=青／課題=橙／
チケット=紫／ToDo=灰）を付け、タスク以外のまとまりの前に区切りを挟んでいます。
課題とチケットの行には「課題」「チケット」の小さな印も付きます。
チケットについては次のとおりです。

- 期限切れ → 期限の近い順 → 優先度の高い順で出ます
- 見出しに「未割当 N 件」も出るので、誰も受けていないものに気づけます
- 行を押すとチケットの詳細が開き、状態や担当をその場で変えられます
- チケットが 1 件もなければ、この欄そのものが出ません

### 左メニューの並び順を変える

**プロフィール設定 > 左メニューの並び順** で、よく使うものを上に動かせます。
`↑` `↓` で並べ替えて「並び順を保存」を押すと、**自分の画面だけ**に反映されます。

- 「既定の並びに戻す」でいつでも元に戻せます
- **スマホでは、上から 4 つが画面下のタブ**になります
- あとから機能が増えたときは、その項目が末尾に足されます（設定は消えません）

### メモやコメントに書いた URL

`https://` または `http://` で始まる URL は、**そのまま書くだけでリンクになります**。
記法を覚える必要はありません。

- 別タブで開きます（`rel="noopener noreferrer nofollow"` 付き）
- 日本語を含む URL、`?a=1&b=2` のようなクエリもそのまま扱います
- 末尾の「。」「、」や、囲みの「）」は URL に含めません
- 長い URL は途中を省いて表示します（実際に開くのは省略前の URL です）
- `example.com` のようにスキームの無い文字列は、誤爆を避けるためリンクにしません

タスクのメモと課題の「内容・背景」「対応方針・結果」は、ふだんは**本文のまま表示**され、
クリックすると編集に切り替わります（リンクを踏んだときは編集に入りません）。
`Ctrl+Enter` で保存、`Esc` で取り消しです。

> 社内ファイルサーバーへの `\\server\share\...` や `file://` は、ブラウザの制限で
> 本文中のリンクからは開けません。**「リンク・ファイル」欄**から登録してください。

### コメントでメンバーを呼ぶ（@メンション）

タスクや課題のコメント欄で **`@`** を打つと、そのプロジェクトのメンバー一覧が出ます。
↑↓ で選んで Enter（またはクリック）で挿入されます。

- 呼ばれた人には**「◯◯さんがあなたを呼んでいます」**という専用の通知が届きます。
  担当者でもコメント参加者でもない人を、名前だけで呼び出せます
- 呼ばれた人には通常のコメント通知は送りません（二重に届かないようにするため）
- **そのプロジェクトのメンバーだけ**が対象です。部外者の名前を書いても通知は飛びません
- 送信すると「◯◯ さんに通知しました」と表示されるので、狙った相手に届いたか確認できます
- 通知の要否は「プロフィール設定 > メール通知 > 名前を呼ばれたとき」で切り替えられます

書き方はある程度ゆるく解釈します。

| 書き方 | 結果 |
|---|---|
| `@佐藤 花子` `@佐藤花子` | 氏名（空白あり・なしどちらでも） |
| `＠佐藤 花子` | 全角の＠ |
| `@佐藤 花子さん` `@佐藤 花子、` | 敬称や句読点が続いても可 |
| `@sato` `@sato@example.com` | メールアドレス（またはその左側） |
| `@鈴木` | 姓だけ。**ただしその姓の人が一人に決まるときだけ** |

同姓の人が複数いる場合は、誤って別人へ通知しないよう**どちらにも送りません**。
フルネームで書くか、候補から選んでください。

### 横断検索

画面右上の検索窓（**`/` キー**でも開きます）に 2 文字以上入れると、
タスク・課題・コメント・プロジェクト・自分の ToDo をまとめて探します。

- 結果は種類ごとにまとまり、選ぶとその詳細が開きます（↑↓ キーでも選べます）
- **参加していないプロジェクトのものは出ません。**コメントの中身も同じ扱いです
- ToDo は自分のものだけが対象です

### マイ ToDo（プロジェクトに属さない用事）

左メニューの **「📝 マイ ToDo」**。プロジェクトに紐づけるほどでもない用事を置く場所です。

- **自分にしか見えません。**管理者にも見えません（API も本人のものしか返しません）
- 入力は「やること」1 行だけ。Enter でどんどん追加できます。期限は任意
- チェックを入れると完了。「完了も表示」で済んだものも振り返れます
- 行にカーソルを合わせると出るボタンで、期限の設定・削除ができます。
  タイトルはクリックすると、その場で書き換えられます
- **📁 ボタンでプロジェクトのタスクに引き上げられます。**「ちょっとした用事のつもりが
  ちゃんとした案件になった」ときに、書き直さずに移せます（期限とメモも引き継ぎます）
- 未完了のものは「今日の確認」にも出てくるので、朝の確認で一緒に片付けられます

#### 繰り返しの ToDo

決まった日にやることは、右上の **「🔁 繰り返し」** から登録しておけます。

- 毎日 / 毎週（曜日指定）/ 毎月（日指定）の 3 通り。「間隔」で 1 回とばしにもできます
- **「何日前に出すか」** を決められます。たとえば *毎月 1 日* のことを *3 日前* にすると、
  毎月 28 日ごろに ToDo として出てきます（その月に無い日は月末に寄ります）
- 入力中に「◯月◯日の予定 → ◯月◯日に ToDo が出ます」と出るので、確かめてから保存できます
- 出てきた ToDo には 🔁 が付きます。消しても次回はまた出ます
- 「今すぐ出す」「⏭ 次回を飛ばす」で、その回だけ前倒し・見送りができます
- 規則そのものも**自分にしか見えません**。繰り返しをやめても、すでに出ている ToDo は残ります
- 出るきっかけは日次バッチと、**自分が ToDo か「今日の確認」を開いたとき**の両方です。
  バッチを止めていても、画面を開けばその場で出てきます

### 全プロジェクトのガント

左メニューの **「📊 全体ガント」**。参加しているプロジェクトをまとめて 1 枚に並べます。

- 既定でプロジェクトごとに区切り行が入り、その中の親子関係はそのまま保たれます
- 区切り行の `▼` でプロジェクトごとたためるので、関係するところだけ開けます
- バーのドラッグで日程も変えられます（そのプロジェクトの編集権限がある場合）
- 「区切り」を担当者やカテゴリに変えると、**プロジェクトをまたいだ担当者別の並び**になります
- PowerPoint 出力も同じようにできます

### マイタスクで先の見通しを掴む

「マイタスク」の上に **「これからの山」** が出ます。今週から 12 週ぶんの件数を棒で並べたものです。

- 「1 か月後あたりに固まっている」といった**寄り**が一目で分かります
- 棒をクリックすると**その週だけ**に絞り込めます（もう一度押すと解除）
- 期限切れ・3 か月より先・期限なしの件数は棒の下にまとめて出ます
- 一覧そのものも **期限超過 / 今日 / 今週中 / 来週 / 1か月以内 / それ以降 / 期限なし** に
  区切って並ぶので、スクロールしながら時期を見失いません
- 「自分の担当」で見ているあいだは、**担当者の列は出ません**（全部自分になるため）。
  「すべて」に切り替えると出ます

### タスクリスト

- 行をクリック → 詳細ドロワー（メモ・子タスク・先行タスク・添付・コメント）
- 行をドラッグ → 並べ替え。**行の中央にドロップすると子タスクになります**（上端／下端は同階層で前後移動）
- `⋯` メニュー → 上下の並べ替え・階層の移動・子タスク追加・編集・完了切替・削除
- 検索、担当者、状態で絞り込み。絞り込み時も親階層は表示され続けます
- **プロジェクトを切り替えると、直前に見ていたタブのまま移ります**。ガントを見ている
  ときに別のプロジェクトを選べば、そのプロジェクトのガントが開きます
- **一覧は既定で「未完了のみ」**です。ガントは既定で完了も表示するため、
  「ガントには出るのに一覧に無い」ということが起きます。何かが隠れているときは
  一覧の上に **「未完了のみ で絞り込み中 — 7 件を隠しています［すべて表示］」**
  と出るので、1クリックで解除できます

#### Excel / CSV からまとめて取り込む

タスク一覧の右上 **「⬆ 取り込み」** から。既存の計画表をそのまま流し込めます。

1. Excel で範囲を選んでコピーし、**貼り付け欄にそのまま貼る**（CSV ファイルを選んでも構いません。
   UTF-8 でも Shift_JIS でも読めます）
2. 列の対応づけは見出しから自動で推測します。違っていればその場で直せます
3. **「確認する」**で、登録せずに問題点だけ先に見られます
4. 「取り込む」で登録

- **タスク名の先頭を字下げすると、そのまま子タスクになります**（全角スペースでも半角2つでも可）。
  「階層」列（1, 2, 3…）や「親タスク名」列を用意しても構いません
- 日付は `2026/10/1` `2026-10-01` `2026年10月1日` `10/1(水)` などをそのまま読みます
- カテゴリ・重要度・状態は**日本語の表示名のまま**で通ります（「設計・企画」「高」「進行中」など）
- 担当者は氏名かメールアドレスで照合します。**プロジェクトのメンバーにいない人**は
  行番号つきで知らせたうえで、担当者なしとして取り込みます
- 一度に取り込めるのは 1000 行までです

#### まとめて編集する

一覧の各行のチェックボックスで選ぶと、上部に操作バーが出ます。

| 操作 | 内容 |
|---|---|
| 担当者・状態・カテゴリ | 選んだタスクにまとめて適用 |
| 期限 | 全部を同じ期限にそろえる |
| 📆 日程をずらす | 開始日と期限を同じ日数だけ前後に動かす（マイナスで前倒し） |
| 🗑 削除 | 子タスクごとまとめて削除 |

変更内容は各タスクの履歴に「一括更新 — 状態: 進行中」のように残ります。

#### 並び順を入れ替える

| 操作 | 場所 | できること |
|---|---|---|
| ドラッグ＆ドロップ | 一覧（PC） | 行の**上のほう**に落とせばその上へ、**下のほう**なら下へ |
| `⋯` メニュー | 一覧（PC・スマホ） | 「↑ 上へ移動」「↓ 下へ移動」 |

ドラッグ中は、いま落とすとどうなるかがカーソルの横に出ます。

- **「この上に移動」「この下に移動」**（青）… 並べ替え
- **「◯◯ の子にする」**（オレンジ）… 階層の移動

行の上下 35% が並べ替え、真ん中 30% が「子にする」です。並べ替えのほうが
使う頻度が高いので、子にする帯は狭くしてあります。先頭のタスクには
「↑ 上へ移動」は出ません（末尾も同様）。

#### 同じ名前のタスクがあるとき

「週次定例」のような名前は複数できがちです。取り違えないように、
**親を選ぶ場面では、同名のタスクにだけ上位の道のりを添えます**。

```
週次定例
  トップレベル
週次定例
  開発フェーズ
```

タスクの編集画面の「親タスク」も同じく「週次定例（開発フェーズ）」のように出ます。
名前が重複していないタスクには何も付かないので、ふだんの見え方は変わりません。

#### 親子関係を組み替える

やり方は 3 通りあります。**ドラッグはスマホでは使えない**ので、外出先では
`⋯` メニューか詳細ドロワーを使ってください。

| 操作 | 場所 | できること |
|---|---|---|
| ドラッグ＆ドロップ | 一覧（PC） | 行の中央に重ねてその子にする。上端・下端は同じ階層で前後に移動 |
| `⋯` メニュー | 一覧（PC・スマホ） | 「直前のタスクの子にする」「一つ上の階層に出す」「親タスクを変更…」 |
| 詳細ドロワー | どこからでも | 先頭の「親タスク」欄から「変更」または「⇤ 一つ上へ」 |

- 「親タスクを変更…」では全タスクをツリー表示し、名前で絞り込めます。
  自分自身と自分の子孫は候補から外れ、入れると 8 階層を超える相手は選べません。
- 子タスクは**まとめて付いてきます**。深さの判定も、動かすタスク単体ではなく
  その下にぶら下がる子孫まで数えて行います。
- 付け替えたタスクは移動先の**末尾**に置かれます。変更はタスクの履歴
  （「親タスク: A → B」）に残ります。

### 自然言語でタスクを登録する

画面右上の **「⚡ クイック追加」**（または `n` キー）で、やることを一文入力します。

```
来週金曜までに鈴木さんが移行手順書を作成
```

これを次のように解釈して、**登録前に確認できる下書き**にします。

| 読み取るもの | 例 |
|---|---|
| 期限・開始日 | 今日／明日／明後日／今週中／来週金曜／今月末／来月末／3日後／2週間後／9/30／2027-01-15／`10/1から10/20まで` |
| 担当者 | 登録済みユーザー名（「鈴木さん」「@佐藤 花子」「担当: 高橋」） |
| カテゴリ | 「調査」「設計」「実装」「資料」「会議」「申請」「障害」などの語から推定 |
| 重要度 | 至急・緊急・最優先→最重要／重要・急ぎ→高／急がない→低 |
| プロジェクト | 文中にプロジェクト名があれば割り当て |
| マイルストーン | 「納期」「リリース日」などの語 |

読み取った語はタスク名から取り除かれ、「移行手順書の作成」のような簡潔な名前になります。
2行目以降はメモとして扱われます。

### タスクを子タスクに分解する

タスク詳細の子タスク欄にある **「✨ 分解を提案」**、またはクイック追加の
「登録したあとに子タスクの分解案を出す」から使います。

「サーバ移行」と入れると、次のような候補が並びます。

> 現行環境の調査・棚卸し → 移行計画と切り戻し手順の作成 → 移行先環境の構築 →
> 事前バックアップの取得 → 検証環境での移行リハーサル → 関係者への切替日程の周知 →
> 本番切替作業 → 疎通確認・動作検証 → 監視・バックアップ設定の移行 →
> 旧環境の停止 → 移行完了報告

- チェックを外せば不要な工程は登録されません。名前・区分・期限はその場で直せます
- 親タスクに開始日と期限が入っていれば、**工程の重みに応じて日程を自動で割り振ります**
- 標準では 12 種類の定型テンプレート（システム移行／リリース／障害対応／調査・比較検討／
  ツール導入／資料作成／開発／監査／契約・購買／採用／イベント運営／引き継ぎ）から選ばれます

### 会議メモからまとめて起票する

プロジェクトのタスク画面の **「📝 メモから」** を押して、議事録をそのまま貼り付けます。

```
9/20 リリース準備定例
出席: 鈴木、佐藤、高橋

・DBスキーマの残件を鈴木さんが今週金曜までに片付ける
・フロントのスマホ対応、佐藤さんが来週水曜までに
・結合テストの環境、高橋さんが月末までに用意する（優先度高め）
・リリース判定会は10/9で調整中 → 日程確定したら別途
・監視まわりの話は次回に持ち越し
```

「🔍 やることを拾う」を押すと、上の例からは 3 件だけが候補に並びます。

| タスク名 | 担当 | 期限 | 重要度 |
|---|---|---|---|
| DBスキーマ残件対応 | 鈴木 一郎 | 2026-09-25 | 中 |
| フロントのスマホ対応 | 佐藤 花子 | 2026-09-23 | 中 |
| 結合テスト環境の準備 | 高橋 美咲 | 2026-09-30 | 高 |

- **やると決まったことだけ**を拾います。「調整中」「次回に持ち越し」は候補になりません
- 「鈴木さん」のような書き方でも登録済みの氏名に結びつけます。
  同じ姓の人が複数いるときは、取り違えるより未割当のままにします
- 相対的な日付は今日を基準に解釈します。曜日から出した日付が過去になる場合は次に来るその曜日に送ります
- 並んだあとは画面で直せます。要らないものはチェックを外してください
- 「確認する」を押すと、登録せずに問題だけ先に確認できます
- Claude 連携が無効なときは、**1 行 1 件として読み取る簡易動作**になります（その旨が画面に出ます）

### 今週の進行を見てもらう

プロジェクトの **ボトルネック**画面にある「🤖 今週の見立てを聞く」を押すと、
その時点の数字をまとめて渡して、進行上の危ないところを書いてもらえます。

渡しているのは次の内容だけです（いずれも画面に出ている数字と同じものです）。

- 期限を過ぎている未完了タスク
- クリティカルパスの並び
- 他の作業を止めているタスクと、待たせている件数
- 前後関係と日程が矛盾しているところ
- 14 日以上動いていない未完了タスク
- 担当者ごとの週あたりの負荷（時間 / 使える時間）
- これから来るマイルストーン

返ってくるのは「ひとことの要約」「危ないところ 2〜4 件（根拠・打ち手つき）」
「今週まず手を付けるなら 1〜3 件」です。タスク名はそのまま詳細に飛べます。

- **ボタンを押したときだけ**問い合わせます。自動では実行しません（20 秒ほどかかります）
- 一度聞いた見立ては**画面を移動しても残ります**（24 時間で消えます）。
  見出しに「いつの数字で書いたか」が出るので、古くなったら「聞き直す」を押してください
- Claude 連携が無効なときは、このカード自体が表示されません
- あくまで渡した数字をもとにした見立てです。判断の材料としてお使いください

### Claude 連携（任意）

上の2つは**外部サービスなしで動きます**。より自由な文章や、テンプレートにない作業の分解を
扱いたい場合は、Claude API を有効にできます。

```bash
# サーバー側で一度だけ
/opt/task-manager/.venv/bin/pip install -r /opt/task-manager/requirements-optional.txt
```

そのうえで「管理 > システム設定 > Claude 連携」で API キーを入れて有効にします。

- 有効にすると、解析と分解が Claude に切り替わります（画面には「🤖 Claude 解析」と表示）
- 「📝 メモから」の読み取りと、ボトルネック画面の「進行レビュー」も使えるようになります
- いずれも**人がボタンを押したときだけ**問い合わせます。定期実行はしません
- **API がエラーになった場合は自動的にルールベースへ戻る**ので、登録が止まることはありません
- タスクの文面が Anthropic に送信されます。社内規程を確認のうえ有効にしてください
- 既定の依存関係は PyMySQL のみのままです。anthropic を入れなければこの機能は無効のままになります

接続テストが失敗したときは、**失敗した理由がそのまま画面に表示されます**。よくある原因:

| 表示 | 対処 |
|---|---|
| サーバーに anthropic パッケージが入っていません | 上の `pip install` を実行する |
| API キーが未設定です / 形式が正しくありません | `sk-ant-` で始まるキーを入力して保存する |
| APIキーが正しくありません | キーが失効・無効。Anthropic Console で再発行する |
| Claude API エラー (400): … | メッセージ本文に原因が入っています。モデル名やアカウントの権限を確認してください |
| Claude API に接続できませんでした | サーバーから api.anthropic.com への通信（HTTPS 443）が塞がれていないか確認 |

### 工数と負荷を見る

プロジェクトの **「📈 負荷」** タブ（全プロジェクト横断は `#/workload`）で見られます。

- **週別の負荷ヒートマップ** — 見積工数を営業日で割り、担当者ごとに週単位で積み上げます。
  1人あたりの上限（既定 40h/週）を超えた週は赤、8割超は橙で表示します
- **見積精度** — 完了タスクの「実績 ÷ 見積」。見積の癖が数字で見えます
- **未計画のタスク** — 開始日も期限もないタスクは負荷に反映できないため、別枠で件数を出します

工数は**すべて任意項目**です。入力を増やしたくない場合はそのままで構いません。
**1件も入っていなくても、担当タスクの件数で負荷が見えます**（表示が自動で件数に切り替わります）。

入力する場所は3つあり、どれも埋めなくても動きます。

| 場所 | 何を入れるか |
|---|---|
| タスクの作成・編集 | 見積 (h) — 期間の欄の隣 |
| タスク詳細 | 見積 (h) / 実績 (h) |
| 今日の確認 | 実績h — 進捗ボタンの隣。**入れた分が実績工数に加算されます** |

進捗率が入っていれば、残りの工数だけを負荷として数えます（40h の作業が 75% 完了なら残り 10h）。

### 祝日と会社の休業日

「管理 > システム設定 > 稼働時間と休日」で **「日本の祝日を休みとして扱う」** を有効にすると
（既定で有効）、次のように反映されます。

- **ガントチャート**: 土日と同じように網掛けし、日付の下に「祝」と出ます（名前はマウスを載せると出ます）
- **負荷ビュー**: その週に使える時間が祝日のぶん減ります。
  たとえば 3 連休のある週は 40h → 16h になり、同じ仕事量でも過負荷として色が変わります

祝日は**外部サービスに問い合わせず、その場で計算します**（社内に閉じた構成のままにするため）。
春分・秋分の日、ハッピーマンデー、振替休日、祝日に挟まれた「国民の休日」まで自動で求めます。

年末年始や夏季休暇など会社独自の休みは、同じ画面の **「会社の休業日」** に日付と名前で追加します。

### 定例タスクを自動で起票する

タスク一覧の **「🔁 定例」**、または任意のタスクの `⋯` メニューから **「定例にする」** で登録します。
既存のタスクから作れば、名前・担当・カテゴリ・見積がそのまま引き継がれます。

| 設定 | 内容 |
|---|---|
| 繰り返し | 毎週（曜日を複数選択可）／毎月（日を指定、月末は自動調整）／毎日 |
| 間隔 | 1 なら毎回、2 なら1回とばし（隔週・隔月） |
| 何日前に作るか | 期限の N 日前にタスクを起票します（既定 3 日前） |

日次バッチが起票します。「今すぐ作る」で手動生成もできます。長期間サーバーを止めていた場合でも、
古い分をまとめて作ることはありません（30日より前の分は飛ばして次回日に進みます）。

#### 週1の打ち合わせを、ひとつのタスクとしてまとめる

毎回が別々のタスクとして並ぶと、ガントが埋まってしまいます。**束ねる親タスク**を
決めておくと、1行で扱えます。

1. 「週次定例（9月〜12月）」のような**親タスク**を、期間ぶんの日付で作る
2. 定例タスクの設定で **「まとめる親タスク」** にそれを選ぶ

こうすると、

- 毎回のタスクがその子として作られます
- ガントでは**親を折りたたんで1行**。バーは親に指定した期間（9月〜12月）のまま、
  子が増えても縮みません
- 進捗は「17回中5回完了 → 29%」のように**自動で集計**されます
- **各回にコメントや議事録のリンクを残せます**

#### 予定どおりにいかないとき

生成された各回は**ふつうのタスク**なので、規則とは切り離して扱えます。

| 状況 | やること |
|---|---|
| 今週だけ日程がずれた | その回のバーをドラッグ、または期限を変更。規則は動きません |
| 臨時の打ち合わせが入った | 親タスクの `⋯` から「＋ 子タスクを追加」 |
| 今週は中止 | その回のタスクを削除。規則は次回へ進んでいるので**再生成されません** |
| 来週は休みと分かっている | 一覧の **「⏭ 次回を飛ばす」**。作らずに次回日だけ進みます |

自動で作られる回は、**開始日と期限が同じ日**になります（会議のようにその日で
終わるものが多いため）。何日かかける作業を定例にしたい場合は、作られたあとで
開始日を前へずらしてください。

### Slack に通知する

「管理 > システム設定 > Slack 通知」で Incoming Webhook の URL を設定します。

**こちらから送るだけなので、インターネットに公開されたエンドポイントは不要です。**
tailnet 内に閉じた構成のままで使えます。

- 日次バッチのタイミングで、プロジェクトごとに「期限超過 / 本日期限 / 重要な未解決課題」の件数を送信
- 影響度が「高」「重大」の課題が起票されたときに即時送信
- プロジェクト設定で個別の Webhook URL を入れると、**プロジェクトごとに別チャンネル**へ送れます

**流す内容を選べます。** システム設定の「Slack に流す内容」で「課題の起票」「日次サマリ」を
それぞれオン／オフできます。プロジェクト設定で「Slack に流す種類をこのプロジェクトだけ変える」に
チェックを入れると、そのプロジェクトだけ別の組み合わせにできます（チェックしなければ全体設定に従います）。

> Slack **からタスクを登録する**（スラッシュコマンド）には、インターネットから到達できる
> エンドポイントが別途必要になります。通知の送信だけなら現在の構成のまま使えます。

### ボトルネック分析

タスクリスト右上の **「⛔ ボトルネック」** から開きます。先行タスクの設定をたどって、
次の3つを自動で計算します。

| 見出し | 内容 |
|---|---|
| ボトルネック（影響の大きい順） | そのタスクが終わらないと着手できない後続タスクを、**間接的な依存も含めて**数えてランキングします。ランキングの根拠（「後続 6 件が待機」「クリティカルパス上」「期限 3 日超過」など）を必ず併記します |
| クリティカルパス | 依存関係と各タスクの期間から最長経路を求めます。ここが1日遅れると、プロジェクト全体の完了が1日遅れます |
| 依存関係と日程の矛盾 | 「先行タスクの期限」が「後続タスクの開始日」より後になっている組み合わせを検出します。日程を引き直す目安になります |

タスクリストとガントにも同じ情報が出ます。

- `⛔ 6` … このタスクの後続6件が待っている
- `⏳ 待ち` … 先行タスクが未完了で、まだ着手できない
- `CP` と行の赤い縦線 … クリティカルパス上のタスク
- ガントの**赤枠のバー**＝クリティカルパス、**赤い実線の矢印**＝日程が矛盾している依存

タスク詳細では「このタスクが遅れると影響する範囲」に、直後だけでなく間接的に影響する
タスクまで一覧表示します。

### 課題管理表

プロジェクトの **「課題」** タブ、またはサイドバーの **「課題」**（全プロジェクト横断）から開きます。
タスク（やること）とは別に、**判断・調整が必要な事柄**を記録して追跡するための一覧です。

| 項目 | 内容 |
|---|---|
| No. | プロジェクトごとの通し番号。自動採番されます |
| 区分 | 仕様・要件／技術・実装／スケジュール／体制・リソース／コスト・予算／品質・不具合／外部・他部門／その他 |
| 影響度 | 低・中・重要度と同じ4段階（低／中／高／重大）。重大は行の左に赤線が付きます |
| 状態 | 未対応／対応中／保留／解決済／クローズ。解決済・クローズにすると**解決日が自動で入ります** |
| 対応者・起票者 | 対応者を設定すると本人に通知が飛びます |
| 発生日・対応期限・解決日 | 期限が近い／超過している課題は色で警告します |
| 内容・背景／対応方針・結果 | それぞれ自由記述。詳細画面から直接編集できます |
| 関連タスク | この課題に関係するタスクを複数紐づけられます |
| 経緯・コメント | 状態や対応者の変更は自動で履歴に残り、追記もできます。ファイルや URL の添付も可能 |

**タスクとの紐づけ**は双方向に見えます。

- 課題の詳細 → 「関連タスク」に、紐づいたタスクの状態と進捗が並びます
- タスクの詳細 → 「関連する課題」に、そのタスクが関わる課題が並びます
- 未完了タスクが残っている課題には「この課題に紐づく未完了タスクが N 件あります」と表示されます

右上の **「⬇ CSV」** で、表示中の一覧をそのまま CSV に落とせます（Excel でそのまま開ける
BOM 付き UTF-8）。

サイドバーの **「課題」**（全プロジェクト横断）から起票するときは、
ダイアログの先頭で**どのプロジェクトに出すかを選べます**。
選び直すと、対応者の候補と関連タスクの候補もそのプロジェクトのものに入れ替わります。

### チケット（受付窓口）

サイドバーの **「🎫 チケット」** から開きます。課題管理表がプロジェクトの中の論点を追うのに対し、
こちらは **プロジェクトの外から飛んでくる話を受ける窓口** です。

- 「情シス窓口」「総務」のように**窓口（キュー）ごと**に分けられます（管理 > チケット窓口）
- **ログインしていれば誰でも起票でき、誰でも読めます**。プロジェクトの権限には乗りません
- 削除できるのは**起票した本人と管理者**だけです（対応の記録を他人に消させないため）

| 項目 | 内容 |
|---|---|
| 番号 | 全社通し番号。`#123` で呼べます |
| 種別 | 📋 依頼／💬 問い合わせ／🚨 障害。障害を選ぶと**発生日時**の欄が出ます。窓口ごとに既定を決められます |
| 分類 | その窓口に分類を置いている場合だけ出ます |
| 窓口 | どの受付窓口に出すか。プロジェクト専用の窓口なら、名前の横にプロジェクト名が出ます |
| 状態 | 受付待ち／対応中／保留／完了／取り下げ。完了・取り下げにすると**対応日時が自動で入ります** |
| 優先度 | 低／中／高／緊急。高以上は一覧で色が付きます |
| 依頼元 | 代理で起票したときに「営業部 田中」のように書けます |
| 担当・期限 | 担当に設定すると本人に通知が飛びます |
| 対応時間 | かかった時間（任意）。集計に使えます |
| 内容／対応結果 | 自由記述。詳細画面から直接編集できます |
| やりとり・経緯 | 状態や担当の変更は自動で履歴に残ります。`@名前` で呼べて、ファイルや URL も添付できます |

件数が増えたときは **100 件ずつ** 読み込みます。上の「250 件中 100 件を表示」の
ような表示と、一覧の下の **「さらに読み込む」** で続きを足せます
（課題の横断一覧も同じ形です）。

一覧の上には **未完了／受付待ち／期限超過／今週の完了** が出ます。
「今週の完了」には今月ぶんと通算も添えてあります。残っている数だけだと、
片付けた実感が残らないためです。その下の行に「担当が決まっていないもの」と
「受けてから片付くまで 平均 N 日」が出ます。

#### 日次・週次で数える

一覧の上の **「📊 集計を見る」** を押すと、**受けた数**と**片付いた数**を並べた画面になります。

- 左上の**窓口の選択**で、窓口ごとにも全体にも切り替えられます
- **日次**（7 / 14 / 30 / 60 日）と**週次**（4 / 8 / 12 / 26 週）を切り替えられます
- グラフの上の **← →** で、1 画面ぶんずつ**過去にさかのぼれます**（半年ぶんまで）。
  「今に戻る」で今日までの表示に戻ります
- 「差し引き」が プラスなら、受けたぶんに追いつけていないということです
- 内訳は **担当者ごと**（受けた数・片付けた数・平均日数）、**分類ごと**、**窓口ごと**、
  **種別ごと** の 4 つです。分類は、その窓口に分類を置いているときだけ出ます
- 担当が決まっていないものは「未割当」としてまとめて数えます
- **対応時間**（次項）が入っていれば、合計時間の列と合計カードも出ます
- 右上の **「⬇ CSV」** で、そのままの数字を落とせます
- 窓口タブで絞ってから開くと、その窓口だけの集計になります

受付日は起票した日時、完了日は状態を完了・取り下げにした日時で数えます。
日をまたいだものは、片付けた側の日に入ります。

#### 対応時間を記録する

チケットの詳細と起票画面に **「対応時間 (h)」** の欄があります。**入れなくても構いません。**

- 入れておくと、集計に「かかった時間」の合計と、担当者ごと・分類ごとの内訳が出ます
- 数えるのは**完了・取り下げにしたチケットぶん**だけです（途中のものは足しません）
- 取り込みでも `1.5` や `90分` のように書けます
- 変更はやりとりの履歴に残ります

#### CSV / Excel から取り込む

右上の **「⬆ 取り込み」** から、過去のメールや台帳をまとめて登録できます。
Excel から貼り付ける（タブ区切り）か、CSV ファイルを選びます。

| 使える列 | 書き方 |
|---|---|
| 件名 | 必須 |
| 窓口 | 窓口名。空欄の行は、ダイアログで選んだ窓口に入ります |
| 種別 | 依頼 / 問い合わせ / 障害 |
| 状態 | 受付待ち / 対応中 / 保留 / 完了 / 取り下げ |
| 優先度 | 低 / 中 / 高 / 緊急 または 0〜3 |
| 分類 | その窓口に登録してある分類名 |
| 依頼元 | 「営業部 田中」など |
| 担当 | 氏名またはメールアドレス |
| 期限 | 2026-04-01 / 2026/4/1 / 4月1日 など |
| 発生日時 | 2026-04-01 09:30 など |
| 対応時間 | `1.5` / `90分` / `2h`。空欄でも構いません |
| 内容・対応結果 | 自由記述 |
| 受付日 | 過去ぶんを入れるとき。空欄なら取り込んだ日時 |

- 見出し行があれば**列の対応づけを推測**します。違っていれば画面で直せます
- **「確認する」** を押すと、登録せずに問題だけ先に出せます
  （窓口が見つからない、件名が空、担当者が見つからない など）
- 状態を「完了」にした行は、**受付日と同じ日時で完了したもの**として入ります

#### タスクや課題へ渡す

チケットを開くと、下の 2 つのボタンがあります。

- **「＋ タスクにする」** — プロジェクトを選ぶと、チケットの内容を説明に写したタスクを作ります。
  依頼元・期限・担当も引き継ぎます。受付待ちのままだった場合は「対応中」に進みます
- **「＋ 課題にする」** — 作業ではなく、決めないと進まない論点だったときに、
  プロジェクトの課題管理表へ移します

すでにあるタスクには **「既存に紐づけ」** でつなげます。「それはこの作業でやっています」と
返せるようにするためのものです。紐づけたあとは両方から行き来できます。タスクの詳細と課題の詳細にも
**「関連チケット」**が出るので、「この作業はどの依頼から来たのか」をあとから辿れます。
**チケットを消してもタスクや課題は残ります**（逆も同じで、リンクだけが外れます）。

タスクを追加できるのは**自分が編集できるプロジェクト**だけです。
チケット自体は誰でも読めますが、他人のプロジェクトへ勝手に作業を積むことはできません。

#### 窓口を増やす

サイドバーの **管理 > 📮 チケット窓口** を開き、右上の **「＋ 窓口を追加」** から作ります
（管理者のみ）。決められるのは次の項目です。

| 項目 | 内容 |
|---|---|
| 窓口名 | 「情シス窓口」「総務」など。重複はできません |
| 説明 | 何を受ける窓口かをひとこと |
| プロジェクト | 特定のプロジェクト専用の窓口にする場合に選びます（次項） |
| 起票したときの種別 | この窓口で最初から選ばれている種別。障害窓口なら「障害」にしておけます |
| 分類 | この窓口の中の分け方（次項）。置かなくても構いません |
| 記号・色 | 一覧のタブや行に出ます。記号は用意した 30 種から選びます |
| 並び順 | 小さいほど左（上）に出ます。10 刻みにしておくと後から間に挟めます |
| 新しい起票を受け付ける | 外すと **「受付停止」**。新しい起票だけ止まり、過去のものは読めます |

チケットが残っている窓口は削除できません。先に移すか、受付停止にしてください。

#### 窓口ごとの分類

窓口ごとに「PC・端末」「ネットワーク」「アカウント」のような**分類**を置けます。
タスクのカテゴリとは別で、**窓口ごとに中身が違ってよい**のがこの機能です。

- 分類を置いた窓口では、起票と詳細に「分類」の欄が出ます（置かなければ出ません）
- 一覧では分類のチップが出て、その窓口を選んでいるときだけ分類で絞り込めます
- 集計にも**分類ごと**の内訳が並びます
- 名前や色はあとから変えられます。**チケットの紐づけは名前ではなく行そのものを見ている**ので、
  リネームしても過去のチケットはそのまま付いてきます
- 分類を消すと、それを使っていたチケットは「分類なし」に戻ります
- 別の窓口へチケットを移すと、分類は外れます（分類は窓口ごとのものなので）

#### プロジェクト専用の窓口にする

窓口に **プロジェクト** を紐づけると、「このプロジェクトへの問い合わせ窓口」になります。

- その窓口のチケットを **「タスクにする」「課題にする」** とき、
  そのプロジェクトが**最初から選ばれます**（毎回選ばなくて済みます）
- 一覧の窓口タブと、チケットの見出しに、どのプロジェクト向けかが出ます
- `GET /api/tickets?project_id=…` で、そのプロジェクト宛てのチケットだけを取れます

プロジェクト専用の窓口に未完了のチケットがあると、そのプロジェクトのタブに
**「🎫 チケット」** が出ます（押すとその窓口で絞った一覧が開きます）。

紐づけても **誰が読めるかは変わりません**。チケットはこれまでどおり社内の誰でも読めます。
一方、**タスクや課題を作れるのは自分が編集できるプロジェクトだけ**なので、
プロジェクト外の人が窓口に依頼を出すことはできても、
そのプロジェクトへ勝手に作業を積むことはできません。

プロジェクトが終了（アーカイブ）しても窓口と過去のチケットは残ります。
プロジェクト自体を削除した場合は、紐づけだけが外れて窓口は残ります。

### ガントチャート

- **バーをドラッグして日程を変更できます**（編集権限がある場合）
  - バーの真ん中をドラッグ → 期間を保ったまま前後にスライド
  - バーの左右の端をドラッグ → 開始日・期限だけを伸縮
  - マイルストーン（◆）はドラッグで日付を移動
  - ドラッグ中は変更後の日付が吹き出しで出ます。1日単位で吸着します
  - 画面の端まで運ぶと自動で横スクロールします
  - 子タスクを持つ行は子から日程を集計しているため、ドラッグ対象外です
- **タスクの追加**（編集権限がある場合）
  - 一番下の **「＋ 新しいタスク」** 行を**ドラッグすると、その期間で**追加の画面が開きます
    （開始日と期限が入った状態で開くので、名前を入れるだけで済みます）
  - 同じ行のタスク名側をクリックすると、日付なしで追加の画面が開きます
  - 画面右上の **「＋ タスク」** からも追加できます
- **タスクが増えて見づらくなったとき**
  - **折りたたみ**: 親タスクの `▼` で子をたたみます。たたんだ親には `(3)` のように
    子の数が出ます。「⤡ 折りたたみ」で一括、「⤢ 展開」で戻せます。
    **この開閉はタスク一覧と共有**されるので、両方の画面で同じ見え方になります
  - **区切り**: ツールバーの「区切り」で並べ方を変えられます

    | 区切り | 見え方 |
    |---|---|
    | なし | 階層のまま |
    | フェーズ（既定） | トップレベルのタスクごとに太い罫線と薄い帯を入れる |
    | 担当者 | 担当者ごとに**区切り行**を挟む（誰がいつ何をやるかが一目で分かります） |
    | カテゴリ | カテゴリごとに区切り行を挟む |

    担当者・カテゴリの区切り行は、左端に色、右端に件数が出ます。
    行の `▼` でそのグループ全体をたためます
- **バーの横に出す項目**を「日付 / 担当者 / 進捗」から選べます。全部外して
  バーだけにもできます。選んだ状態は次回も引き継がれ、**PowerPoint 出力にも
  そのまま反映**されます
- **繰り返しを1行で見せる**（「たたんだ行に各回」）

  親タスクを折りたたむと、隠れた子の期限が記号で並び、1行で全体が見えます。

  ```
  週次定例  ├◇──◇──◇──◇──◇──◇──◇──◇──◇──┤  3/12
  月次報告  ├──────★──────────★──────────★┤  0/3
  ```

  - 済んだ回は色が変わります。右端に「3/12」と回数が出ます
  - 記号をクリックすると、その回の詳細が開きます
  - **記号はタスクごとに選べます**（タスクの編集 >「ガントの記号」）。
    ◆ ひし形 / ● 丸 / ■ 四角 / ▲ 三角 / ▼ 逆三角 / ★ 星。
    系列ごとに変えると、週次と月次が一目で区別できます
  - マイルストーンの印にも同じ記号が使われます
  - 不要ならツールバーの「たたんだ行に各回」を外すと、従来の集約バーに戻ります
- 表示単位（日／週／月）と期間を切り替え。「自分の担当のみ」で絞り込み
- **色分け**を「状態 / カテゴリ / 重要度」から選択（凡例も連動します）
- 親タスクは細いサマリーバー、マイルストーンは◆、依存関係は破線矢印で表示
- バーやタスク名をクリックすると詳細が開きます

#### ロードマップ表示

ツールバーの **「表示: ガント / ロードマップ」** で切り替えます。長い期間の全体像を
1 枚にまとめて見せたいとき（経営報告や計画レビューなど）に使います。

| | ガント | ロードマップ |
|---|---|---|
| 行 | すべてのタスクを階層で表示 | **トップレベルのタスク（＝フェーズ）だけ** |
| マイルストーン | 各行に◆ | **上部の専用レーン**にピンで並べ、縦の点線で全体に落とす |
| 目盛り | 日／週／月 | **四半期**（年と Q1〜Q4） |
| 帯 | 細いバー | 太い帯。**中にフェーズ名と進捗率**を表示 |
| 幅 | 期間ぶん横スクロール | **画面幅にぴったり収める** |
| 依存の矢印 | 表示 | 非表示（線を減らして読みやすく） |

- フェーズの期間・進捗は子タスクから自動集計されるので、**追加の入力は要りません**。
  大きな塊をトップレベルのタスクにして、その下に実作業をぶら下げてください
- 節目にしたいタスクは「マイルストーンとして表示する」にチェックを入れると、
  階層のどこにあってもロードマップの上部レーンに出ます
- ロードマップは見せるための図なので、バーのドラッグ編集はガント表示のときだけ有効です

#### PowerPoint への貼り付け

1. ガント画面右上の **「⬇ エクスポート」**
2. 出力サイズを選ぶ（既定は **PowerPoint 16:9 = 1280×720px**、高精細にしたい場合は「2倍」）
3. 形式を選ぶ
   - **PNG**（推奨）… そのままスライドに貼り付け。スライド全面にぴったり収まります
   - **SVG** … 拡大しても劣化しないベクター形式。PowerPoint の「挿入 > 画像」から取り込め、
     図形に変換して個別編集もできます
4. 「スライド幅いっぱいに広げる」を有効にすると、期間の長さに応じて目盛り幅を自動調整し、
   余白の少ない図になります

ロードマップ表示のまま書き出すと、四半期の目盛りを保ったままスライド幅に合わせます
（ファイル名も `プロジェクト名_ロードマップ_日付.png` になります）。

## 状態とカテゴリを自分たちの言葉にする

「管理 > 🎨 状態とカテゴリ」で変えられます。

### 状態

名前・色・並び順を変えられます。

- 色は 12 色の見本から選ぶか、任意の色を指定できます
- **配色セット**（標準／落ち着いた色／はっきりした色／暖色より／単色）を選ぶと

- 削除すると、そのカテゴリを使っていたタスクは**未分類に戻ります**（消える前に確認します）
- 変更は絞り込み・ガントの色分け・凡例・CSV・Claude 連携にもそのまま反映されます

| ロール | 権限 |
|---|---|
| 管理者 (admin) | 全プロジェクトにオーナーとしてアクセス。ユーザー・グループ・システム設定を管理 |

### プロジェクト単位の権限

| 権限 | 閲覧 | コメント | タスク編集 | 設定変更・削除 |
|---|:-:|:-:|:-:|:-:|
| オーナー | ○ | ○ | ○ | ○ |
| 編集者 | ○ | ○ | ○ | — |
| コメント可 | ○ | ○ | — | — |
| 閲覧のみ | ○ | — | — | — |

- ユーザー個別とグループの両方で設定でき、**強い方の権限**が適用されます
- グループは「管理 > グループ」で作成し、部署やチーム単位でまとめて権限を付与できます

### メンバーの登録

「プロジェクト」画面のカードで、参加している人の顔が並びます。オーナーは顔の列か
**「メンバー」** ボタンから、ユーザー個別／グループ単位で権限を設定できます。

### 見える範囲

参加していないプロジェクトは、**どの入口からも見えません**。

- プロジェクト一覧、横断のタスク検索、課題一覧、負荷ビュー、「今日の確認」から除外されます
- URL を直接叩いても 403 になります
- 通知メールと日次レポートにも出ません（在籍中に割り当てられ、その後メンバーから
  外れたタスクも同じです）
- **メンバーでない人は担当者・対応者に指定できません**。指定しようとすると
  「◯◯ さんはこのプロジェクトのメンバーではありません」と表示されるので、
  先にメンバーへ追加してください（見えないタスクを抱えさせないための制限です）
- 担当者を選ぶプルダウンには、そのプロジェクトのメンバーだけが並びます

管理者 (admin) はすべてのプロジェクトを見られます。これは運用上の必要による例外です
（ただし他人の「マイ ToDo」だけは管理者にも見えません）。

## メール通知と日次サマリ

「管理 > システム設定」で設定します。

1. **メール送信を有効にする** をオンにする
2. SMTP ホスト／ポート／認証情報／送信元アドレスを入力
   （ポート 465 は SSL、それ以外で STARTTLS を使う場合はチェックを入れる）
3. **アプリの URL** を入力（通知メール内のリンクに使われます）
4. 「テストメールを送る」で疎通確認

### 通知が飛ぶタイミング

| 種類 | 契機 |
|---|---|
| 担当者に設定 | 他の人からタスクを割り当てられたとき |
| コメント | 担当タスク・自分が作成したタスク・自分がコメントしたタスクに新しいコメントが付いたとき |
| 期限間近 / 本日期限 / 期限超過 | 日次バッチ実行時（同じタスク・同じ日の重複通知はしません） |
| 日次サマリ | 設定した時刻に、対応が必要なタスクがある人だけに送信 |

通知一覧では、**押すとその対象が開きます**（タスク・課題・チケットのいずれか）。
開く先がない知らせ（日次サマリなど）はカーソルが変わらないので、押せるかどうかが分かります。

### 通知をどこまで送るか調整する

「送る／送らない」は 3 段階で決まります。**どれか一つでも「送らない」なら送りません。**

| 段階 | 設定場所 | 効きかた |
|---|---|---|
| プロジェクト | プロジェクト設定 > 「このプロジェクトの通知を送る」 | オフにすると、そのプロジェクト発の通知をメール・Slack・画面の通知すべて止めます |
| 受け取る人 | プロフィール設定 > メール通知 | 「通知をメールでも受け取る」が親スイッチ。その下で種類ごとに選べます |
| 受け取る人 × プロジェクト | プロフィール設定 > 「プロジェクトごとの受け取り」 | チェックを外したプロジェクトからは、メールも日次レポートも届きません |

種類ごとの指定は「担当に設定されたとき」「コメントがついたとき」「期限が近い / 超過したとき」
「日次レポート」の 4 つです。たとえば「自分に割り当てられたタスクだけメールで欲しい」なら、
担当だけを残して他を外します。

これらは**メール送信の可否**だけを決めます。画面右上のベル（アプリ内通知）には通知が残るので、
メールを止めても見落としません。ただしプロジェクト側でオフにした場合は、アプリ内通知も作られません。

### 日次バッチの実行方法

アプリ内スケジューラが既定で動作します（「日次サマリを自動送信する」＋送信時刻を設定）。
アプリを複数プロセスで動かす場合や、cron で管理したい場合は `--no-scheduler` で起動し、
次のように cron から実行してください。

```cron
0 9 * * 1-5 cd /opt/task_manager && .venv/bin/python server.py --run-digest >> /var/log/task-manager-digest.log 2>&1
```

日次レポートは、本人がミュートしたプロジェクトと、通知を止めているプロジェクトのタスクを除いて集計します。

## 本番運用

### サブディレクトリ配下で公開する

`https://example.co.jp/tasks/` のように、既存サイトのサブディレクトリで動かせます。
1 つのドメインに複数のアプリを相乗りさせたい場合に使ってください。**ビルドし直しは不要です。**

前段のプロキシが「プレフィックスを削るかどうか」で設定が変わります。どちらでも動きます。

#### パターンA: プロキシがプレフィックスを削らない（nginx など）

アプリ側にパスを教えます。

```ini
; config.ini
[server]
base_path = /tasks
```

インストーラなら `sudo ./deploy/install.sh --base-path /tasks` で設定されます。
nginx 側は `proxy_pass` の**末尾にスラッシュを付けない**のがポイントです。

```nginx
location /tasks/ {
    proxy_pass       http://127.0.0.1:8080;   # 末尾に / を付けない
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

この構成ではセッション Cookie の `Path` も `/tasks` に限定されます。

#### パターンB: プロキシがプレフィックスを削る（Tailscale serve など）

アプリはルートで動いたまま、ブラウザからはサブディレクトリに見える構成です。
`base_path` は**空のまま**にしてください。

```bash
sudo tailscale serve --bg --set-path /tasks http://127.0.0.1:8080
```

nginx で同じことをする場合は `proxy_pass http://127.0.0.1:8080/;`（末尾に `/` を付ける）です。

この構成ではアプリが外側のパスを知らないため Cookie の `Path` が `/` になります。
同じドメインの他アプリにも Cookie が送られるのが気になる場合だけ、次を設定してください。

```ini
[server]
cookie_path = /tasks
```

#### 共通の設定

「管理 > システム設定 > アプリの URL」を `https://example.co.jp/tasks` にしてください
（通知メール内のリンクに使われます）。

> **仕組み**: 画面側は `location.pathname` を基準に URL を組み立てます。ハッシュルーティング
> なのでパスは常にアプリ自身を指し、どの階層に置いても正しく解決されます。サーバー側は
> `base_path` が設定されていれば受け取ったパスからそれを取り除いてから通常どおり処理し、
> 末尾スラッシュなしの `/tasks` は `/tasks/` にリダイレクトします。

### 更新する（git pull）

**スキーマの差分を手で当てる必要はありません。** アプリは起動のたびに

1. `CREATE TABLE IF NOT EXISTS`（新しいテーブルを作る）
2. 列・索引・外部キー・NULL 許可の移行（`app/db.py` の `MIGRATIONS` ほか）
3. 新しい設定項目の既定値の投入

を流します。いずれも**何度実行しても同じ結果**になるようにしてあるので、手順は
「バックアップ → pull → 再起動 → 確認」だけです。

```bash
# 1. 念のため先にバックアップ（数秒で終わります）
sudo systemctl start task-manager-backup.service

# 2. 取得して再起動
cd /opt/task-manager && git pull
sudo systemctl restart task-manager

# 3. スキーマが最新か確かめる
.venv/bin/python server.py --check-schema
```

`--check-schema` は**データベースを一切変更せず**、足りないテーブル・列・索引・
設定項目だけを表示します。問題がなければ終了コード 0、差分があれば 1 を返すので
監視にも使えます。

画面側は**ふつうにリロードすれば新しいものに入れ替わります**（ハードリロードや
キャッシュ削除は不要です）。JavaScript と CSS には `Cache-Control: no-cache` と
`ETag` を付けてあり、ブラウザは毎回サーバーに確認し、変わっていなければ
304（本文なし）で済ませます。期限つきのキャッシュではないので、更新が遅れて
反映されることはありません。

```
接続先: tmapp@127.0.0.1:3306/task_manager
テーブル数: 28
スキーマは最新です。
```

何が適用されたかはログに残ります。

```bash
journalctl -u task-manager -n 30 | grep -i スキーマ
# → tm.db: スキーマを移行しました (1 件): projects.slack_events
```

> **開発者向け**: 既存テーブルに列を足したときは、`DDL` だけでなく
> `MIGRATIONS`（索引なら `MIGRATION_INDEXES`、外部キーなら `MIGRATION_FKS`、
> NOT NULL を外したなら `NULLABLE_COLUMNS`）にも必ず追記してください。
> 書き忘れると**新規インストールでは動くのに既存環境だけ壊れます**。
> `tests/test_migration.py` が初版のスキーマ（`tests/fixtures/schema-v1.sql`）と
> 突き合わせて、この追記漏れを検出します。

### 別のサーバーへデプロイする

移すものは **アプリ本体・データベース・添付ファイル（`data/uploads/`）** の3つだけです。
`deploy/install.sh` が、ユーザー作成から systemd 登録までをまとめて行います。

#### 1. 移設先サーバーの準備

必要なのは Python 3.8 以上と MariaDB / MySQL だけです。

```bash
# RHEL 系
sudo dnf install -y python3 mariadb105-server
sudo systemctl enable --now mariadb
# Debian / Ubuntu 系
sudo apt install -y python3 python3-venv mariadb-server
sudo systemctl enable --now mariadb
```

#### 2. アプリを転送する

```bash
# 移設元で（.venv・data・config.ini は含めない）
tar czf task-manager-app.tar.gz \
    --exclude='.venv' --exclude='data' --exclude='config.ini' \
    --exclude='__pycache__' --exclude='*.pyc' \
    server.py requirements.txt README.md app static docs deploy config.ini.example

scp task-manager-app.tar.gz 新サーバー:/tmp/
```

```bash
# 移設先で
mkdir -p ~/tm-src && tar xzf /tmp/task-manager-app.tar.gz -C ~/tm-src
cd ~/tm-src
sudo ./deploy/install.sh --create-db
```

`--create-db` を付けるとデータベースとアプリ用ユーザーを自動で作り、パスワードを生成して
`config.ini` に書き込みます。完了時に **初期管理者のパスワードが1度だけ表示される**ので控えてください。

主なオプション（既定値のままなら指定不要です）:

| オプション | 既定 | 用途 |
|---|---|---|
| `--dir PATH` | `/opt/task-manager` | インストール先 |
| `--user NAME` | `taskmgr` | 実行ユーザー |
| `--port N` / `--bind ADDR` | `8080` / `127.0.0.1` | 待ち受け |
| `--db-name` / `--db-user` / `--db-password` | `task_manager` / `tmapp` / 自動生成 | 接続先 |
| `--db-host` / `--db-port` | `127.0.0.1` / `3306` | 外部 DB を使う場合 |
| `--service NAME` | `task-manager` | systemd サービス名 |
| `--no-service` | — | systemd に登録しない |

#### 3. 既存データを移行する

移設元でアーカイブを作り、移設先で流し込みます。

```bash
# 移設元
./deploy/backup.sh /tmp                       # /tmp/task-manager-YYYYmmdd-HHMM.tar.gz
scp /tmp/task-manager-*.tar.gz 新サーバー:/tmp/
```

```bash
# 移設先
tar xzf /tmp/task-manager-*.tar.gz -C /tmp
BUNDLE=$(ls -d /tmp/task-manager-2*)

sudo systemctl stop task-manager
sudo mysql task_manager < $BUNDLE/database.sql
sudo cp -a $BUNDLE/uploads/. /opt/task-manager/data/uploads/
sudo chown -R taskmgr:taskmgr /opt/task-manager/data
sudo systemctl start task-manager
```

ユーザーのパスワードやセッションもそのまま引き継がれます。移行後は
「管理 > システム設定」の **アプリの URL** を新しいホスト名に変更してください
（通知メール内のリンクに使われます）。

#### 4. HTTPS で公開する

社内だけなら Tailscale（下記）、社外に出すなら nginx + Let's Encrypt が簡単です。
どちらの場合も `config.ini` の `secure_cookie = 1` を忘れずに設定してください。

#### 5. バージョンアップ

同じコマンドをもう一度実行するだけです。`config.ini` と `data/` は保持され、
データベースのスキーマ変更（マイグレーション）も自動で適用されます。

```bash
cd ~/tm-src && tar xzf /tmp/task-manager-app.tar.gz    # 新しいアーカイブを展開
sudo ./deploy/install.sh                               # サービス停止 → 更新 → 再起動
```

> **オフライン環境の場合**: 依存は PyMySQL 1つだけです。インターネットに出られない場合は
> `pip download PyMySQL -d wheels` で取得した wheel を持ち込み、
> `sudo /opt/task-manager/.venv/bin/pip install wheels/PyMySQL-*.whl` を実行してから
> `--no-service` なしで再度 install.sh を流してください。

### systemd で常駐させる

[`deploy/task-manager.service`](deploy/task-manager.service) を

### Tailscale 経由で HTTPS 公開する（この環境の現行構成）

Tailscale を入れているサーバーなら、証明書の準備なしで HTTPS 公開できます
（Tailscale が Let's Encrypt から自動取得・自動更新します）。443 番が別のアプリで
埋まっている場合は、次のように別ポートに載せられます。

```bash
# アプリは 127.0.0.1:8080 のみで待ち受け（config.ini の host = 127.0.0.1）
# tailnet からは tailscale serve 経由の HTTPS だけで到達できる
sudo tailscale serve --bg --https=8443 http://127.0.0.1:8080
```

アクセス先: **https://＜ノード名＞.＜テールネット名＞.ts.net:8443/**
（`tailscale status` や `tailscale cert --help` で自分のノードの FQDN を確認できます）

- `--bg` で登録しているため、設定は tailscaled に保存され再起動後も有効です
- Funnel（インターネット公開）は**有効にしていません**。tailnet 内からのみアクセスできます
- 併せて `config.ini` に `secure_cookie = 1` を設定し、セッション Cookie に `Secure` 属性を付けています
- 通知メール内のリンク用に、システム設定の「アプリの URL」を上記の URL に設定してください

解除する場合:

```bash
sudo tailscale serve --https=8443 off
```

サーバー本体は systemd で常駐させています。

```bash
sudo systemctl status task-manager     # 状態確認
sudo journalctl -u task-manager -f     # ログ
sudo systemctl restart task-manager    # 再起動
```

> 参考: 443 番の既存設定はフォアグラウンド実行（`tailscale serve` を `--bg` なしで起動）のため、
> そのプロセスが終了すると 443 の公開も止まります。恒久化するなら同様に `--bg` での登録が確実です。

### 一般的な HTTPS 公開（リバースプロキシ）

社外からアクセスする場合は必ず HTTPS 化してください。
[`deploy/nginx.conf.example`](deploy/nginx.conf.example) を参考にリバースプロキシを立て、
`config.ini` の `secure_cookie = 1` を設定します（セッション Cookie に `Secure` 属性が付きます）。

### 静的ファイルのキャッシュ

| 対象 | ヘッダー | ねらい |
|---|---|---|
| `index.html` | `Cache-Control: no-store` | 入口は必ず最新を取る |
| JS / CSS / 画像 | `Cache-Control: no-cache` + `ETag` + `Last-Modified` | 毎回確認し、変わっていなければ 304。更新は即座に反映される |
| API の応答 | `Cache-Control: no-store` | 古いデータを掴ませない |

`no-cache` は「キャッシュしない」ではなく「**使う前に必ず確認する**」という意味です。
実測では、変更していないファイルはすべて 304（本文なし）で返るため、
毎回リロードしても通信量はほとんど増えません。

ビルド工程を持たない構成なので、ファイル名にハッシュを付ける方式は採らず、
サーバー側での検証に寄せています。

### 性能について

3,000 タスク / 12 プロジェクト / 8 人の想定でひととおり測り、詰まるところを直しました。

| 処理 | 前 | 後 |
|---|---|---|
| 期限スキャン（日次バッチ） | 8,373 ms / 9,852 クエリ | **164 ms / 39 クエリ** |
| プロジェクト一覧 | 件数ぶん問い合わせ | 件数によらず一定 |
| 全体ガント（API） | 219 ms | 150 ms |
| 全体ガント（画面） | 2,266 ms | 1,372 ms |

- 日次バッチは、通知の可否判定を 1 件ずつ問い合わせていたのをまとめ、
  登録も 1 件ずつの INSERT からまとめ書きに変えました
- プロジェクト一覧はメンバーと権限をプロジェクトごとに引いていたのを 1 回にまとめました
- 俯瞰ガントは、図に要る列だけを返すようにし、初回は親をたたんだ状態で開きます
- ガントは **600 行を超えると打ち切り**、「絞ってください」と表示します。
  黙って重くなるより、状況が分かるほうがよいという判断です

いずれも `tests/test_api.py` に問い合わせ回数の回帰テストを入れてあるので、
あとから N+1 が混ざれば落ちます。

### セキュリティ上の実装

- パスワードは PBKDF2-HMAC-SHA256（20万回ストレッチ）で保存
- セッションは HttpOnly・SameSite=Lax の Cookie（既定 14 日）
- 更新系リクエストは Origin ヘッダーを検証（CSRF 対策）
- SQL は全てプレースホルダ経由。画面描画も DOM API で組み立てており HTML インジェクションを防止
- 添付ファイルはランダムなファイル名で保存し、ダウンロード時に権限を再確認

## バックアップ

対象は **データベース** と **添付ファイル（`data/uploads/`）** の 2 つです。

付属のスクリプトが両方まとめて1つのアーカイブにします。

```bash
/opt/task-manager/deploy/backup.sh /backup      # /backup/task-manager-YYYYmmdd-HHMM.tar.gz
```

### 定期バックアップ（systemd タイマー）

`deploy/backup-rotate.sh` が取得と世代管理をまとめて行います。既定は
**日次 7 世代 + 週次 4 世代**、保存先は `/var/backups/task-manager` です。

```bash
sudo cp deploy/task-manager-backup.service deploy/task-manager-backup.timer /etc/systemd/system/
sudo mkdir -p /var/backups/task-manager && sudo chown "$USER" /var/backups/task-manager
sudo systemctl daemon-reload
sudo systemctl enable --now task-manager-backup.timer
```

- 毎日 02:30 に実行します（`RandomizedDelaySec=10m`）。**サーバーが止まっていて
  実行できなかった分は、起動後に取り返します**（`Persistent=true`）
- 取得後に `tar tzf` で展開できるか、`database.sql` が入っているかを確かめ、
  おかしければ 0 以外で終了します（`systemctl status` に失敗が残ります）
- 週次は日曜のアーカイブを `weekly/` に**ハードリンク**するだけなので容量は増えません
- 保存先・世代数は環境変数で変えられます

```bash
BACKUP_DIR=/data/backup KEEP_DAILY=14 KEEP_WEEKLY=8 ./deploy/backup-rotate.sh
```

状態の確認:

```bash
systemctl list-timers task-manager-backup.timer
journalctl -u task-manager-backup -n 20
ls -la /var/backups/task-manager/daily /var/backups/task-manager/weekly
```

> 保存先が同じディスクだと、ディスク障害には無力です。定期的に別マシンや
> オブジェクトストレージへ持ち出すことをおすすめします。

### 復元できるか確かめる

バックアップは「取れていること」ではなく「戻せること」が大事なので、ときどき
別のデータベースへ流し込んで確認してください。

```bash
tar xzf /var/backups/task-manager/daily/task-manager-YYYYmmdd-HHMM.tar.gz
sudo mysql -e "CREATE DATABASE tm_restore_check CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
sudo mysql tm_restore_check < task-manager-*/database.sql
sudo mysql tm_restore_check -e "SELECT COUNT(*) FROM tasks;"
sudo mysql -e "DROP DATABASE tm_restore_check;"
```

個別に取る場合:

```bash
mysqldump --single-transaction -u tmapp -p task_manager | gzip > /backup/task_manager_$(date +%F).sql.gz
tar czf /backup/uploads_$(date +%F).tar.gz -C /opt/task-manager data/uploads
```

### テストの実行

テスト用データベースを作ってから実行します（テストのたびに中身は初期化されます）。

```bash
sudo mysql -e "CREATE DATABASE task_manager_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
               GRANT ALL PRIVILEGES ON task_manager_test.* TO 'tmapp'@'localhost'; FLUSH PRIVILEGES;"

TM_DB_PASSWORD='アプリ用ユーザーのパスワード' .venv/bin/python -m unittest discover -s tests -v
```

テストは `config.ini` を読まず、環境変数と既定値だけで動きます（`TM_DB_NAME`
既定 `task_manager_test`、`TM_DB_USER` 既定 `tmapp`）。実行のたびにテスト用
データベースの中身は作り直されるので、本番の DB 名を指定しないでください。
